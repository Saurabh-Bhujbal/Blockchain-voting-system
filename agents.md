## 🎯 Project Summary

**SecureVote** is a decentralized electronic voting system that uses:
- **Ethereum smart contracts** (Solidity) deployed on a local Ganache blockchain for immutable vote storage
- **FastAPI** (Python) backend for user authentication, registration, and DeepFace-powered biometric face recognition
- **Express.js** (Node.js) server for serving the frontend, JWT middleware, and file uploads
- **MySQL** database for storing voter credentials, roles, and face encodings
- **Vanilla HTML/CSS/JS** frontend with Browserify bundles for Web3 interaction

The system enforces a **two-factor authentication flow**: password verification → face recognition → JWT token issuance.

## ⚠️ Critical Rules & Constraints

### DO NOT
- **Do NOT modify `build/contracts/`** — these are auto-generated by `truffle migrate`. If you change `Voting.sol`, run `truffle migrate --reset` to regenerate.
- **Do NOT enable admin registration** — `/adminRegister.html` and `/register-admin` are intentionally blocked (403). Admins are seeded via SQL only.
- **Do NOT change the JWT SECRET_KEY** in one `.env` without changing the other — the root `.env` and `Database_API/.env` must share the same `SECRET_KEY`.
- **Do NOT use `app.js` directly in HTML** — it must be bundled via `npm run build:app` into `src/dist/app.bundle.js` first (it uses `require()` statements).
- **Do NOT add new npm packages without rebuilding** — after installing, run `npm run build:app` to regenerate the bundle.

### IMPORTANT PATTERNS
1. **Authentication is URL-based** — JWT tokens are passed as `?Authorization=Bearer%20<token>` query parameters, NOT in HTTP headers. The Express `authorizeUser` middleware reads from `req.query.Authorization`.
2. **Two-step login** — Step 1: `GET /login` verifies password → Step 2: `POST /face/login` verifies face and returns JWT. Never bypass face verification.
3. **Roles** — Database `role` field is either `'user'` (voter) or `'admin'`. The login flow uses `expected_role` to gate access.
4. **Face encoding** — Stored as JSON string of 128 floats (FaceNet embedding) in `voters_base.face_encoding` column.
5. **Contract interaction** — All blockchain reads/writes happen client-side via `src/js/app.js` using `@truffle/contract` and `web3`. The browser connects to Ganache at `127.0.0.1:7545` via MetaMask.

## 🧩 Key Code Locations

### When modifying authentication:
- Password logic: `Database_API/main.py` → `get_role()` function (line ~105)
- Face recognition: `Database_API/main.py` → `face_login()` (line ~225) and `face_register()` (line ~181)
- Frontend face flow: `src/js/faceRecognition.js` — handles webcam, capture, and API calls
- Frontend password flow: `src/js/login.js` — handles login form submission
- JWT verification: `index.js` → `authorizeUser` middleware (line ~30)

### When modifying elections/voting:
- Smart contract: `contracts/Voting.sol` — all on-chain logic
- Frontend contract calls: `src/js/app.js` — `App.loadCandidates()`, `App.vote()`, `App.loadElectionsDropdown()`
- Election management UI: `src/html/addCandidate.html` + `src/css/manage.css`

### When modifying the UI/design:
- Global design tokens: `src/css/theme.css` — CSS variables, navbar, footer, buttons
- Page-specific styles: `src/css/login.css`, `index.css`, `admin.css`, `manage.css`, `results.css`
- Landing page: `src/html/landing.html` (self-contained, 35KB, includes inline styles)

### When modifying results display:
- Admin results: `src/html/viewResults.html` — inline `<script>` builds bar chart from `#boxCandidate` table rows
- Voter results: `src/html/voterResults.html` — same pattern, shows winner spotlight
- Results styling: `src/css/results.css` — bar charts, animations, winner card

## 🔧 Common Development Tasks

### Add a new HTML page
1. Create the HTML file in `src/html/`
2. Add a route in `index.js`:
   - Public: `app.get('/page.html', (req, res) => res.sendFile(...))`
   - Protected: `app.get('/page.html', authorizeUser, (req, res) => res.sendFile(...))`
3. Link any CSS/JS files — add routes for them in `index.js` if not already covered

### Add a new API endpoint
1. Add the endpoint in `Database_API/main.py`
2. If the frontend needs to call it, ensure CORS allows it (already configured for `localhost:8080`)
3. Update the CSP header in the relevant HTML file if needed (`connect-src`)

### Modify the smart contract
1. Edit `contracts/Voting.sol`
2. Run `truffle migrate --reset` to recompile and redeploy
3. Run `npm run build:app` to bundle the updated ABI
4. Update any JS code in `src/js/app.js` that calls the contract
5. Rebuild: `npm run build:app`

### Add a new CSS file
1. Create in `src/css/`
2. Add a route in `index.js`: `app.get('/css/newfile.css', ...)`
3. Link it in the relevant HTML: `<link rel="stylesheet" href="../css/newfile.css">`

### Change the database schema
1. Alter the table in MySQL
2. Update `Database_API/main.py` queries accordingly
3. Update `Database_API/seed_admin.sql` if admin seed is affected

## 🧪 Testing Notes

- **No automated test suite exists.** Testing is manual.
- To test login: use a registered voter_id and password, then verify face via webcam.
- To test voting: ensure MetaMask is connected to Ganache network, select an election, vote.
- To test results: navigate to viewResults.html (admin) or voterResults.html (voter) after casting votes.
- Face recognition requires a webcam and sufficient lighting for DeepFace to detect a face.

## 💡 Tips for AI Agents

1. **Always check `index.js` route list** before adding new pages — Express does NOT auto-serve files.
2. **After modifying `src/js/app.js`**, you MUST run `npm run build:app` for changes to take effect.
3. **The `src/dist/` bundles are the actual files loaded by browsers** — never edit them directly.
4. **Inline `<script>` blocks in HTML pages** contain page-specific logic (auth redirects, UI builders). These are NOT bundled.
5. **CSS follows a layered architecture**: `theme.css` (base) → page-specific CSS. Always define new variables in `theme.css`.
6. **The landing page (`landing.html`) is massive (35KB)** with many inline styles — treat it as mostly self-contained.
7. **Admin registration is a security-sensitive area** — it's intentionally locked down. Do not re-enable without explicit user approval.
8. **Both `.env` files must stay in sync** for `SECRET_KEY` — JWT tokens are issued by FastAPI and verified by Express.
